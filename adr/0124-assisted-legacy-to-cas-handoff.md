# ADR 0124 — Explicit, non-destructive live legacy → CAS-only handoff

Date: 22 November 2026 · Status: accepted for #171 (parent #139).

## Context

The existing legacy preview copy (#141) can insert the active project as an IndexedDB row without overwriting it, but does not enter the CAS-only editor. Conversely the root-level opt-in CAS workspace (#167) unmounts `LegacyFactoryApp` with a full reload but does not transfer or select any project. Operators who wish to move from the current legacy project to native CAS have to stitch these together manually and can mistake an existing/diverged/tombstoned IDB project for an empty destination.

The two storage engines (legacy `localStorage` and IndexedDB) cannot participate in one atomic cross-store transaction. The legacy writer lease covers cooperating legacy tabs only; a tab with direct storage access may still modify a project during human consent. CAS-only is same-origin, not cross-device synchronization. The goal here is an explicit *assisted transfer* without claiming global write authority or independent AI/review/test evidence.

## Decision

Add a distinct **Copy ACTIVE project and open in CAS-only** action on the live workspace. It is not a hidden mode switch and does not replace the existing preview copy or CAS-only entry without copy. Gate it with the existing `canNavigateLegacyToCas` contract: same-ID writer lease acquired, exact active raw equals per-ID localStorage canonical slot; no busy state, output/other draft, conflict, project switch, recovery task, writer contention or GitHub autosync. Validate the full project/stack with the CAS strict schema and six coherent stages; refuse any in-flight stage.

The action first performs a **read-only** native `readCasProjectSlot` and permits a transfer **only for missing** destinations. Existing identical/diverged rows are NOT overwritten or silently adopted, and a tombstone cannot be resurrected. The operator must (1) consent to a download of the **exact original per-project localStorage raw JSON** (not a pretty JSON wrapper), (2) acknowledge that backup was actually saved, then (3) explicitly authorize an insert-only copy with the same ID and a full page reload that unmounts all legacy hooks. Check the active project reference, writer lease, settings autosync and per-ID raw again after all dialogs. `commitLegacyCasHandoff` rechecks source and IDB state, then calls the already implemented `copyLegacyCasTicket`/native `insertCasProjectNeverSeen`. A noncooperating writer racing the final consent either changes local raw (abort before insert) or creates the target IDB slot (native insert refuses it); never retry on a new ID or overwrite. An ambiguous acknowledgement or post-ACK read failure is **not** called a failed copy and does not trigger a second insert; the UI asks the operator to inspect the CAS library and original backup.

After a confirmed IDB insert + exact readback and stable legacy source, compute **SHA-256 of the exact raw JSON**, and navigate with a full reload to `?workspace=cas&casHandoff=<id>&casRevision=1&casDigest=<sha256>`, preserving GitHub Pages pathname and unrelated parameters. URL contains no raw, credential, GitHub or cloud data. The hint is not trusted authority. The root mounts **only** the CAS editor, reads no legacy project, and DOES NOT automatically read or select IndexedDB from the URL. The visible *Verify and explicitly OPEN transferred CAS copy* button performs a source read, matches exact ID/revision/SHA-256, obtains separate consent, and then performs a fresh read+exact comparison before adopting the CAS editor session. A rival write between reload and confirmation or during the dialog causes fail-closed rejection. The user may inspect the library manually instead. Return to legacy removes the three untrusted hint fields and does not merge the CAS project back to localStorage.

Copying preserves all historical project configuration, AI checkpoints, Code Agent history/overrides and GitHub metadata **as historical data**. It does **not** turn previous review claims into verified independent evidence, run tests/CI/runner, transfer session credentials, publish to GitHub or sync with other devices. Existing conservative CAS editor gates (#168-#170) may block certain further mutations when imported history/evidence is present; creating a configuration-only fork (#166) remains the safe alternative. There is deliberately no automatic deletion of legacy or of the copied IDB row.

## Verification

Vitest: route parser and Pages-path-preserving URL, malformed/duplicate hint values and digest, SHA-256 exact raw/source ID/revision check; legacy source/stack/running-stage guards, existing/tombstoned destination, rival local raw during preflight, affirmative consent and lease guard, exact IDB insert ACK and digest-only hint, post-ACK readback uncertainty with no retry.

Real Chromium: full legacy app, exact backup download + three consents, native IDB rev1 with original raw and same ID, full reload to root CAS-only with hint but **no automatic selection**, explicit hinted-open confirmation with two verified IDB reads, return removes hint and legacy raw stays identical. Additional contexts: IDB rival inserts same ID during final consent (blocked), tombstone prevents resurrection, legacy rival modifies per-ID raw during final consent (blocked), and IDB rival updates copied record before hinted open (stale URL refused). Marker `FACTORY_INDEXEDDB_ASSISTED_HANDOFF_E2E_PASS`.

Close #171 only after Factory CI, Pages and Installer CI-approved candidate all `completed/success` on the **same final main SHA**, and verify marker in the real browser CI job logs. Parent #139 and #91/#92/#109/#113 remain open; this is NOT full live async cutover of `LegacyFactoryApp`/CodeAgentPanel/GitHub/cloud.
